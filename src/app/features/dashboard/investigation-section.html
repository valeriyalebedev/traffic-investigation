All three rules are simplified heuristics and can produce false positives and false negatives. Severity indicates investigation priority, not a probability of malicious activity. Conditions are evaluated in order: HIGH first, then MEDIUM, then LOW.

Vulnerability Path Probing Possible scanning

Detection ≥ 3 requests to known sensitive paths from the same IP.
High ≥ 10 requests or ≥ 5 distinct sensitive paths.
Medium ≥ 5 requests or ≥ 3 distinct sensitive paths.
Low Detection threshold met, but neither higher condition applies.
Limitation Relies on a predefined list of sensitive paths. Novel attack paths not in the list are not detected. Response codes are not considered — requests returning 200 are counted equally with 404.

Repeated Failed Resource Unusual traffic

Detection ≥ 5 requests to the same normalized path from the same IP, with ≥ 80% HTTP 4xx responses.
High ≥ 15 requests and ≥ 95% failure rate.
Medium ≥ 10 requests or ≥ 90% failure rate.
Low Detection threshold met, but neither higher condition applies.
Limitation Only HTTP 4xx counts as failure; 5xx is excluded. Path normalization strips query parameters and case, but structurally similar paths with different segments are treated as different resources. Cannot distinguish a misconfigured crawler from intentional probing.

Repeated Request Pattern Potential automation

Detection ≥ 3 consecutive repetitions of the same ordered sequence of ≥ 3 HTTP method + normalized path pairs.
High ≥ 5 repetitions and sequence length ≥ 4.
Medium ≥ 4 repetitions or sequence length ≥ 5.
Low Detection threshold met, but neither higher condition applies.
Limitation Detects exact consecutive repetitions of an ordered sequence of HTTP method and normalized path pairs. This makes the rule explainable and predictable, but restrictive. Similar recurring behavior with occasional interruptions or unrelated requests may not be detected.
Improvement Future improvements could detect recurring behavioral patterns across a longer request history, allowing occasional interruptions and variations, and combining sequence similarity with request frequency and timing regularity.

These findings identify suspicious or potentially automated behavior, not confirmed bots or malicious activity. IP addresses identify traffic sources, not individual users. Further investigation and additional signals are required for reliable classification.
